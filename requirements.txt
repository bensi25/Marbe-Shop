# -------------------------------------------------------
#  3. LOGIN / AUTH-SYSTEM
# -------------------------------------------------------
- Supabase Auth (built-in) mit Email/Passwort
- Registrierung mit E-Mail-Bestätigung (Verification-Link)
- Passwort-vergessen-Flow (Reset-Link per E-Mail)
- Session-Management via Supabase (JWT + Refresh-Tokens)
- Optional: OAuth (Google, Apple) für Social Login (später)
- Schutzmechanismen:
  - Rate-Limiting auf Login/Register-Endpunkte (Supabase-seitig + Custom)
  - Account-Lockout nach X Fehlversuchen (anpassbar)
  - Turnstile/hCaptcha bei Registrierung
  - starke Passwort-Policy (min. 8 Zeichen, Groß-/Kleinbuchstaben, Zahl, Sonderzeichen)
  - Session-Hijacking-Schutz (JWT kurzlebig + Refresh-Token sicher)
- Logout überall (Session-Invalidierung)
- Profilbereich:
  - Adressen verwalten
  - Bestellhistorie einsehen
  - Account löschen (DSGVO — Recht auf Löschung)
- Rollen: Customer / Admin (über Supabase custom claims)
- Gast-Checkout (optional — ohne Registrierung bestellen, aber mit E-Mail für Bestellbestätigung)

# -------------------------------------------------------
#  10. SICHERHEIT (SECURITY) — ANGRIFFSSCHUTZ
# -------------------------------------------------------
# ---- 10.1  Web-Grundschutz ----
- HTTPS-only (HSTS-Header, TLS 1.3)
- Content Security Policy (CSP) — restriktiv, kein inline-Script, Report-URI
- X-Content-Type-Options: nosniff
- X-Frame-Options: DENY (kein Clickjacking)
- Referrer-Policy: strict-origin-when-cross-origin
- Permissions-Policy (eingeschränkte Drittanbieter-Features)
- HttpOnly + Secure + SameSite=Strict/Lax Cookies (Session-Token)

# ---- 10.2  Input-Validierung & Output-Escaping ----
- Alle User-Inputs validieren (Frontend + Backend/Edge Function)
- Whitelist-basierte Validierung (erlaubte Zeichen definieren)
- Parameterized Queries für Supabase/PostgreSQL (nie String-Concatenation)
- HTML-Encoding aller User-generierten Inhalte (XSS-Schutz)
- Kein eval(), kein dangerouslySetInnerHTML (oder equivalent)
- Datei-Upload-Validierung: erlaubte MIME-Types, Größenlimit (max 5 MB/Bild), Virus-Scan
- Stripe-Input validieren (Idempotency-Schlüssel, Beträge korrekt)

# ---- 10.3  CSRF-Schutz ----
- Double-Submit Cookie Pattern oder SameSite-Cookies
- Supabase JWT als CSRF-Token (bei jeder Mutation geprüft)
- Anti-CSRF-Token in jedem Formular

# ---- 10.4  Authentisierung / Session ----
- Supabase JWT kurzlebig (Access Token: 1h, Refresh: 30d)
- Refresh-Token Rotation + Reuse Detection
- Rate-Limiting: Login (3 Versuche/Minute), Registrierung (1/Minute)
- Account Lockout nach 5 Fehlversuchen (mit Zeitstrafe: exponentiell)
- Passwort-Hashing: Supabase verwendet bcrypt (automatisch)
- Keine Auslieferung von User-Secrets im Frontend
- Session-Timeout bei Inaktivität (30 Minuten)
- Geräte-Session-Management (alle aktiven Sessions anzeigen, einzelne beenden)

# ---- 10.5  API / Supabase ----
- RLS (Row Level Security) für ALLE Datenbank-Tabellen zwingend
- Supabase Service-Role Key nur in Edge Functions (nie im Client)
- Supabase anon-key hat minimale Rechte (nur SELECT auf öffentliche Daten)
- Rate-Limiting auf Supabase-Ebene (über Supabase Dashboard)
- CORS auf Ursprung beschränken (nur eigene Domain + Dev-Domains)
- API-Key-Rotation (regelmäßige Erneuerung)

# ---- 10.6  Zahlungssicherheit ----
- PCI-DSS-konform durch Stripe (keine Kartendaten im eigenen System)
- Stripe Webhook-Signatur zwingend prüfen
- Idempotency-Header für Payment-Intents
- Transaktions-Logging (wer, wann, was, Betrag, IP)
- Betrugserkennung: Stripe Radar + manuelle Review verdächtiger Orders

# ---- 10.7  Infrastruktur ----
- Regelmäßige Abhängigkeits-Audits (npm audit / Dependabot / Renovate)
- Supabase SSL/TLS für gesamte Datenbank-Kommunikation
- Environment-Variablen (nie hartcodierte Secrets)
- CORS-Whitelist (nur eigene Domain + ggf. Dev-Domains)
- Regelmäßige Sicherheitsupdates (automatisiert via Dependabot)
- Separate Umgebungen: Development → Staging → Production

# ---- 10.8  Weitere Schutzmaßnahmen ----
- Turnstile/hCaptcha auf Login & Registrierung
- Brute-Force-Schutz: progressive Verzögerung nach Fehlversuchen
- Logging von Sicherheitsvorfällen (Login-Fails, verdächtige Requests, 4xx/5xx)
- Regelmäßige Security-Audits (manuell + automatisierte Scanner wie OWASP ZAP)
- Dependency-Check: bekannte CVEs in Drittanbieter-Bibliotheken
- Penetrationstests vor Launch (mindestens automatisierte Scans)
- Notfallplan bei Sicherheitsvorfall (Incident Response)
- Security-Headers automatisiert setzen (via Middleware oder Hosting-Konfig)
- Subresource-Integrity (SRI) für externe CSS/JS-Libraries

#  11. DSGVO / DATENSCHUTZ (GDPR)
# -------------------------------------------------------
# ---- 11.1  Rechtskonformität ----
- Impressum (§5 TMG / §18 MStV) — Pflicht in DE
- Datenschutzerklärung (Art. 13, 14 DSGVO)
  - Welche Daten werden erhoben?
  - Wofür werden sie genutzt?
  - Auf welcher Rechtsgrundlage? (Art. 6 DSGVO)
  - Wie lange werden sie gespeichert?
- AGB (Allgemeine Geschäftsbedingungen) — juristisch geprüft
- Widerrufsbelehrung (für Fernabsatzverträge)
- Cookie-Consent (Einwilligung für nicht-notwendige Cookies)
- Datenschutz-Folgenabschätzung (Art. 35) — empfohlen, da personenbezogene Daten

# ---- 11.2  Technische Umsetzung ----
- Cookie-Consent-Banner mit granularer Auswahl
  - Notwendig: Session-Cookie, CSRF-Token, CSRF-Cookie
  - Optional: Analytics (Matomo/Plausible), Marketing (Newsletter-Tracking)
  - Speicherung der Einwilligung (mit Datum, Zeitpunkt & Umfang) → consent_log-Tabelle
- Datenminimierung:
  - Nur notwendige Daten erheben (Name, Adresse, Zahlung)
  - Keine Geburtsdaten (außer gesetzlich nötig)
  - Keine Tracking-Cookies ohne Einwilligung
  - Keine Speicherung von IP-Adressen (oder nur anonymisiert)
  - Keine Speicherung von Zahlungsdaten
- Verschlüsselung:
  - Transportverschlüsselung (HTTPS/TLS 1.3)
  - DB-Speicherung: Supabase pgcrypto für sensitive Felder
  - Keine plain-text Passwörter (Supabase bcrypt automatisch)

# ---- 11.3  Betroffenenrechte (Art. 15–22 DSGVO) ----
- Recht auf Auskunft (Art. 15):
  - Eigenes Profil mit allen gespeicherten Daten exportierbar (JSON)
  - Automatisierte Zusammenstellung aller Daten (Edge Function)
- Recht auf Berichtigung (Art. 16):
  - Profil- und Adressdaten selbst ändern
- Recht auf Löschung (Art. 17):
  - "Account löschen" — löscht Profil, Adressen, Newsletter-Abo
  - Rechnungsdaten müssen 10 Jahre aufbewahrt werden (steuerrechtlich)
    → Anonymisierung statt Löschung bei Bestelldaten (Name → "gelöschter Nutzer")
  - Bestellhistorie bleibt erhalten, aber ohne Personenbezug
- Recht auf Einschränkung der Verarbeitung (Art. 18)
- Recht auf Datenübertragbarkeit (Art. 20):
  - Datenexport (PDF/JSON) über "Mein Konto"
  - Export aller Bestelldaten, Konfigurationen, Profildaten
- Widerspruchsrecht (Art. 21)
- Automatisierte Entscheidungen (Art. 22) — nicht relevant
- Beschwerderecht bei Aufsichtsbehörde (Art. 77) — in Datenschutzerklärung erwähnen

# ---- 11.4  Auftragsverarbeitung (Art. 28 DSGVO) ----
- AVV (Auftragsverarbeitungsvertrag) mit Supabase erforderlich
  - Supabase bietet DPA (Data Processing Agreement) an
- AVV mit Stripe (Zahlungsdienstleister)
- AVV mit Hosting-Provider (Vercel/Netlify)
- AVV mit E-Mail-Dienst (Resend/SendGrid)
- AVV mit Analytics-Dienst (Matomo/Plausible) — selbst gehostet oder DPA vorhanden
- Keine Datenweitergabe in Drittländer ohne Sicherheitsniveau (Art. 44–49)
  - Supabase: US-Cloud (AWS) → Standardvertragsklauseln (SCC) prüfen
  - Stripe: US → SCC
  - EU-Hosting bevorzugen falls möglich (Supabase EU-Region)

# ---- 11.5  Datensicherheit (Art. 32 DSGVO) ----
- Pseudonymisierung wo möglich
- Verschlüsselung (TLS, DB)
- Zugriffskontrolle (RLS, Rollen, Principle of Least Privilege)
- Regelmäßige Backups (Supabase Point-in-Time Recovery)
- Incident-Response-Plan bei Datenpanne
- Meldepflicht bei Datenschutzverletzung (Art. 33, 34 DSGVO) — Frist: 72h
  - Vorlage für Meldung an Aufsichtsbehörde
  - Vorlage für Benachrichtigung der Betroffenen

# ---- 11.6  Cookie-Consent-Banner ----
- Beim ersten Besuch: Banner mit:
  - "Nur notwendige Cookies" (Funktional)
  - "Alle akzeptieren"
  - "Einstellungen anpassen" (granulare Auswahl mit Checkboxen)
- Speicherung der Präferenz (localStorage + User-Profil)
- Jederzeit änderbar (Footer-Link "Cookie-Einstellungen")
- Detaillierte Aufschlüsselung der Cookies (Name, Zweck, Speicherdauer)

# ---- 11.7  Einwilligungsmanagement ----
- consent_log-Tabelle speichert:
  - user_id (oder anonyme Session-ID)
  - typ (cookie_consent, newsletter, datenschutz_erklärung_gelesen)
  - einwilligung (true/false)
  - umfang (welche Kategorien)
  - timestamp
  - user_agent (anonymisiert)
  - ip (anonymisiert, letztes Oktett = 0)
- Nachweisbarkeit der Einwilligung (Art. 7 DSGVO)

# -------------------------------------------------------
#  13. NEWSLETTER (DSGVO-KONFORM)
# -------------------------------------------------------
- Anmelde-Flow:
  - Double-Opt-In (DOI): E-Mail eingeben → Bestätigungsmail → Klick auf Link → aktiv
  - Bestätigungsmail enthält:
    - Hinweis auf Double-Opt-In
    - Bestätigungs-Link (mit Token, 48h gültig)
    - Datenschutzerklärung-Referenz
  - Nach Bestätigung: Willkommensmail
- Abmelde-Flow:
  - Ein-Klick-Abmeldung (Link in jeder Mail)
  - Bestätigungsseite („Sie wurden abgemeldet")
  - Kein erneuter Versand
- Speicherung:
  - newsletter_subscribers: E-Mail, Status (pending/active/unsubscribed), Anmeldedatum, Opt-In-Datum, Abmeldedatum
  - consent_log: Einwilligungsnachweis (wer, wann, wie)
- DSGVO:
  - Nachweis des Double-Opt-In (IP + Timestamp speichern)
  - Keine Newsletter an inaktive Abonnenten nach 12 Monaten (Erinnerung)
  - Jede Mail: Impressum, Datenschutz-Link, Abmelde-Link
- Versand: Gleicher Dienst wie Transaktionsmails (Resend/SendGrid)
- Inhalt:
  - Neue Kollektionen
  - Sonderangebote
  - Mineralien-Wissen / Blog-Artikel (optional)
  - Geburtstags-Rabatt (optional, nur mit Einwilligung)

#  17. PERFORMANCE-OPTIMIERUNG
# -------------------------------------------------------
- Ladezeit-Ziele:
  - First Contentful Paint (FCP): < 1,0s
  - Largest Contentful Paint (LCP): < 2,5s
  - Gesamtseiten-Größe: < 2 MB (inkl. 3D-Modelle)
  - PageSpeed-Score: > 90 (Google PageSpeed Insights)
- Maßnahmen:
  - Bildoptimierung: WebP-Format, Lazy-Loading, responsive Bilder (srcset)
  - 3D-Modelle: GLTF-Kompression, Auflösungsstufen (Mobile/Desktop)
  - CDN: Cloudflare / bunny.net / Supabase Storage CDN
  - Caching: Supabase Cache-Control-Header, Browser-Caching (max-age)
  - Preload kritischer Ressourcen (Fonts, CSS)
  - Minimierung: CSS/JS-Minify, HTML-Kompression
  - Async-Loading: Nicht-kritische Scripts defer/lazy-loaden
  - Supabase: Index-Optimierung, Query-Performance-Monitoring
  - Edge Functions: Kalte Starts vermeiden (Keep-warm)
  - HTTP/2 oder HTTP/3 (QUIC) nutzen
- Monitoring:
  - Sentry Performance-Tracking
  - Google PageSpeed Insights (regelmäßig)
  - Core Web Vitals im Auge behalten

#  27. RETOUREN-PROZESS
# -------------------------------------------------------
- Widerrufsrecht: 14 Tage (Fernabsatz, gesetzlich)
- Retouren-Flow (Kunde):
  1. "Retoure anmelden" im Kundenkonto (Bestellung auswählen)
  2. Grund angeben (falsche Größe, gefällt nicht, defekt, etc.)
  3. Artikel auswählen (ganze Bestellung oder einzelne Positionen)
  4. Rücksende-Label (PDF) automatisch generieren (DHL)
  5. Paket aufgeben (Filiale oder Abholung)
  6. Rückerstattung nach Wareneingang
- Retouren-Flow (Admin):
  1. Retoure wird angelegt → Status "Retoure angekündigt"
  2. Wareneingang prüfen (Qualitätskontrolle)
  3. Rückerstattung auslösen (via Stripe)
  4. Status "Rückerstattet"
- Kosten:
  - Rücksendung für Kunden kostenlos (DE, Wettbewerbsvorteil)
  - Bei Widerruf: Kosten trägt Unternehmer (§357 BGB)
  - Bei Defekt: Kosten trägt Unternehmer
- DB-Tabellen: returns (Bestell-ID, Grund, Status, Rücksende-Label, erstellt_am, erledigt_am)
- Zustandskontrolle: Fotos bei Erhalt (optional, bei Verdacht auf Abnutzung)
- Frist: Rückerstattung innerhalb von 14 Tagen nach Wareneingang (gesetzlich)

# -------------------------------------------------------
#  37. DATENSCHUTZ-FOLGENABSCHÄTZUNG (DSFA / Art. 35 DSGVO)
# -------------------------------------------------------
- Notwendigkeit: Personenbezogene Daten (Name, Adresse, Zahlung) + Profilbildung (Konfigurator)
- Risiken identifizieren:
  - Unbefugter Zugriff auf Kundendaten
  - Profilbildung durch Konfigurator-Präferenzen
  - Datenpanne (Leak von Adress- und Zahlungsdaten)
  - Weitergabe an Dritte (Versand, Zahlung)
  - Mangelnde Löschmöglichkeit (Recht auf Vergessen)
- Maßnahmen zur Risikominimierung:
  - RLS (Row Level Security) auf ALLEN Tabellen
  - Pseudonymisierung / Anonymisierung nach gesetzlicher Aufbewahrungsfrist
  - Auftragsverarbeitungsverträge (AVV) mit allen Dienstleistern
  - Verschlüsselung (Transport + DB)
  - Zugriffskontrollen (nur Admin, kein Support-Zugriff auf Zahlungsdaten)
- Dokumentation:
  - DSFA schriftlich festhalten
  - Regelmäßig aktualisieren (bei neuen Features / Verarbeitungen)
  - Aufsichtsbehörde: DSFA auf Anfrage vorlegen können
- Verarbeitungsverzeichnis (Art. 30 DSGVO):
  - Alle Verarbeitungstätigkeiten listen (Name, Zweck, Rechtsgrundlage, Datenkategorien, Empfänger, Speicherfrist)
  - Für den Shop: ca. 10-15 Verarbeitungstätigkeiten (Registrierung, Bestellung, Zahlung, Versand, Newsletter, etc.)
